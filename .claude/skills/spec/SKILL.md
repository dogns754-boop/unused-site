# 기획서 작성

대상: `$ARGUMENTS` (프로젝트 이름이 없으면 PROJECTS.md 를 보고 묻는다)

이 단계에서는 **코드를 작성하지 않는다.** `projects/<프로젝트>/PLAN.md` 만 고친다.

1. 현재 PLAN.md 와 README.md 를 읽는다.
2. 비어 있는 부분을 채우기 위해 **한 번에 3~5개의 짧은 질문**을 한다. 이미 답이 나온 것은 묻지 않는다.
   - 어떤 문제를 해결하나? 어떤 상황에서 쓰나?
   - 입력은 무엇이고 결과는 무엇인가? (예시 하나)
   - 데이터는 어디에 저장하나? (파일, 없음, …)
   - 꼭 있어야 하는 것 vs 있으면 좋은 것
3. 답을 바탕으로 PLAN.md 를 작성한다.
   - **2. 핵심 기능**: 체크박스 목록. 각 항목은 `/feature` 한 번(테스트 포함)에 끝낼 수 있는 크기로 쪼갠다.
     구현 순서대로 나열하고, 첫 항목은 "가장 단순하게 끝까지 동작하는 것"으로 한다.
   - **3. 나중에 / 4. 하지 않을 것**: 범위가 커지는 것을 막는 용도. 애매한 건 여기로 보낸다.
   - **5. 기술 결정**: 외부 라이브러리·저장 방식 등 선택과 이유.
   - **6. 작업 기록**: 오늘 날짜로 "기획서 작성" 한 줄.
4. 완성된 기능 목록을 사용자에게 보여주고 확인받는다. 수정 요청이 있으면 반영한다.
5. 확정되면 커밋: `[<프로젝트>] docs: 기획서 작성` (갱신이면 `기획서 갱신`)
6. 다음 단계로 `/feature <프로젝트>` 를 권한다.
