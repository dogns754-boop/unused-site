# 화면 시안 만들기 → 보여주기 → 피드백 반영

대상: `$ARGUMENTS`

PC 프로그램(WPF)·휴대폰 앱은 클라우드에서 띄워 볼 수 없다. 그래서 **화면과 사용 흐름은 HTML 시안으로 먼저 맞추고**, 확정된 시안대로 실제 프로그램을 만든다.

## 1. 만들기
- `projects/<프로젝트>/PLAN.md` 와 기존 `mockup/` 을 읽는다.
- `templates/mockup/index.html` 을 복사해 `projects/<프로젝트>/mockup/<화면>.html` 로 만든다 (이미 있으면 그 파일을 고친다).
  `__NAME__`, `__DESC__` 는 직접 채운다.
- **한 파일로 완결**한다 (외부 파일·라이브러리 없이 HTML/CSS/JS 만).
- 실제 프로그램과 **같은 크기·같은 배치**로 그린다 (예: 도구창 420×120px). 진짜처럼 **동작도 흉내** 낸다:
  버튼을 누르면 "저장됨: 동영상 레퍼런스 3.png" 알림, 범위 창 손잡이를 끌면 크기 변경 등.
- 사용자가 짚을 만한 모든 요소에 `data-ui="한국어 이름"` 을 붙인다 (버튼, 입력칸, 손잡이, 메뉴…).
  같은 이름을 나중에 실제 코드의 컨트롤 이름(x:Name 주석)에도 남겨 두면 대화가 쉬워진다.

## 2. 보여주기
- **클라우드 세션**: Artifact 도구로 게시하고 링크를 준다 (처음 게시 전 `artifact-design` 스킬을 읽는다). 같은 파일을 다시 게시하면 같은 링크가 갱신된다.
  게시 전 직접 확인: Chromium(`/opt/pw-browsers`)으로 스크린샷을 찍어 깨진 곳이 없는지 본다.
- **사용자 PC**: 파일을 브라우저로 연다 (`start projects\<프로젝트>\mockup\<화면>.html`).

## 3. 피드백 받기 — 사용자에게 매번 이렇게 안내
> 오른쪽 아래 **📍 번호 보기** → 고칠 곳 클릭(번호가 복사됨) → 채팅에 붙여넣고 원하는 걸 적어 주세요.
> 예: `[3] 캡처 버튼 1 — 더 크게, 파란색으로` · 화면 캡처에 그림을 그려 보내도 됩니다.

## 4. 반영
- 받은 피드백을 모두 반영해 다시 게시한다. 반영한 항목을 번호별로 한 줄씩 알려준다.
- 사용자가 "이대로 좋아" 하면: PLAN.md `작업 기록` 에 "화면 확정: mockup/<화면>.html" 을 남기고, 다음 단계로 `/feature` 를 권한다.
- 커밋: `[<프로젝트>] docs: <화면> 시안` (수정이면 `시안 수정`)
