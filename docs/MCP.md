# MCP 도구 — 모든 프로젝트가 함께 쓰는 "상위" 도구

**MCP** 는 Claude 에게 끼워 주는 *추가 도구*입니다. 예를 들어 "최신 라이브러리 설명서 찾아보기" 같은 능력을 더해 줍니다.
이 저장소 맨 위의 `.mcp.json` 에 적힌 도구는 **모든 프로젝트에서 자동으로** 쓸 수 있습니다.

## 지금 설치된 것

| 도구 | 종류 | 하는 일 | 어디서 |
|---|---|---|---|
| **Context7** | MCP | 라이브러리의 **최신 공식 설명서**를 찾아 읽음 → 옛날 방식 코드 실수 감소 | 내 PC (클라우드는 네트워크 차단) |
| **REA** | MCP | 프로그램이 **어떻게 동작하는지 분석** (아래 설명) | 어디서나 |
| **Ponytail** v5.2.0 | 규칙 + 명령어 | "게으른 시니어" 규칙 — 짧고 확실한 코드, 테스트·보안은 유지. `/ponytail-review` 코드 검토, `/ponytail-audit` 전체 점검 | 어디서나 (파일로 넣음, [docs/ponytail](ponytail/README.md)) |
| **Figma** | 공식 플러그인 (MCP) | 피그마 디자인을 읽어 화면 코드로 옮김, 디자인 토큰·컴포넌트 추출 | 내 PC · 피그마 로그인 필요 |
| **frontend-design** | 공식 플러그인 (스킬) | "AI 티 나지 않는" 완성도 높은 UI 디자인 원칙 (글꼴·색·여백·배치) | 내 PC |
| **Playwright** | 공식 플러그인 (MCP) | 브라우저를 직접 열어 클릭·스크린샷으로 화면 테스트 (web·Expo 웹 미리보기) | 내 PC |
| **csharp-lsp** | 공식 플러그인 (LSP) | C# 코드의 정의·참조·오류를 정확히 파악 → PC 프로그램 작업 정확도 향상 | 내 PC (`csharp-ls` 필요) |

- **MCP** = Claude 에게 끼워 주는 외부 도구, **플러그인** = MCP·명령어·규칙을 묶은 꾸러미, **스킬** = 특정 작업의 요령서.
- "공식 플러그인"은 Anthropic 공식 모음(`claude-plugins-official`)에 있는 것으로, 가장 믿을 수 있는 경로입니다.
- 클라우드 세션에서는 플러그인이 켜지지 않습니다. 그래서 어디서나 필요한 Ponytail·REA 는 저장소에 직접 넣었습니다.

### 내 PC 에 설치하기

`scripts/setup-windows.ps1` 이 전부 설치합니다 (자세히: [NEW-PC.md](NEW-PC.md)). 설치 후 처음 한 번:

1. Claude Code 에서 "MCP 서버 rea / context7 을 허용할까요?" → **허용**
2. Figma 를 쓰려면: Claude Code 입력창에 `/mcp` → `figma` → **Authenticate** → 브라우저에서 **Allow Access**

## 일부러 넣지 않은 것

| 도구 | 이유 |
|---|---|
| Sequential Thinking 등 "생각 도우미" | Claude 에 이미 같은 기능이 있음 |
| Magic UI·shadcn 등 웹 컴포넌트 MCP | React 웹 전용 — 우리 PC 프로그램(WPF)에는 맞지 않음. web 프로젝트를 하게 되면 추가 |
| Canva·Miro | 개발보다 디자인 결과물 제작용 |

MCP 는 많을수록 Claude 가 매번 읽어야 할 도구 설명이 늘어 오히려 느려지고 헷갈립니다. 꼭 필요한 것만 둡니다.

## REA — 리버스 엔지니어링 도구 (`.mcp.json` 의 `rea`)

[REA (Reverse Engineer Anything)](https://github.com/morluto/rea) — MIT 라이선스, 버전 6.5.0 고정 (`tools/package.json`).
소스 코드 없이 프로그램이 **어떻게 동작하는지** 들여다보는 도구입니다. 결과마다 근거(어느 코드·어느 호출)를 같이 보여줍니다.

### 할 수 있는 것

| 대상 | 무엇을 알려주나 | 필요한 것 |
|---|---|---|
| .NET 프로그램 (C# — 우리 프로그램도 여기) | 클래스·메서드·사용하는 Windows 기능 | 없음 |
| JavaScript / Electron 앱 | 모듈 구조, 기능 흐름 | 없음 |
| 일반 Windows exe (C++ 등) | 함수, 문자열, 호출 관계 | Ghidra 등 분석기 설치 (Windows 지원은 실험 단계) |
| 실행 중인 프로그램의 화면 | 창·버튼 구성, 어떤 동작이 어떤 기능을 부르는지 | 내 PC 에서 실행 |

### 이 워크스페이스에서 쓰는 규칙

| 대상 | 사용 | 이유 |
|---|---|---|
| **우리가 만든 프로그램** (exe 용량, 느린 부분, 버그 추적) | ✅ 자유롭게 | 내 것 |
| **오픈소스 프로그램** (ShareX 등) | ✅ | 라이선스가 허용. 단 GPL 코드 복사는 사용자 확인 |
| **상용 프로그램 동작 원리 분석** (픽픽이 범위 창을 어떻게 띄우는지, 어떤 Windows 기능을 쓰는지) | ✅ 개인용이므로 허용 (사용자 결정 2026-10-16) | 결과물을 혼자만 씀 |
| **상용 프로그램의 코드·아이콘·이미지를 그대로 옮기기** | ❌ | 이해한 내용을 바탕으로 우리 코드로 새로 작성 |

> 상용 프로그램 약관은 보통 리버스 엔지니어링을 금지합니다. 개인용으로 쓰는 범위에서 사용자가 판단해 허용한 것이며,
> 나중에 결과물을 배포·판매하게 되면 이 규칙을 다시 정합니다.

### 설치

- 클라우드 세션: 세션 시작 때 자동 (`scripts/setup.sh`)
- 내 PC: `scripts/setup-windows.ps1` 이 설치. 직접 하려면 저장소 폴더에서 `cd tools && npm install`
- 처음 쓸 때 Claude Code 가 "MCP 서버 rea 를 허용할까요?" 라고 물으면 허용
- 일반 exe 를 깊게 분석하려면 Ghidra 가 따로 필요합니다 — 필요해지면 Claude 가 안내합니다.
