# MCP 도구 — 모든 프로젝트가 함께 쓰는 "상위" 도구

**MCP** 는 Claude 에게 끼워 주는 *추가 도구*입니다. 예를 들어 "최신 라이브러리 설명서 찾아보기" 같은 능력을 더해 줍니다.
이 저장소 맨 위의 `.mcp.json` 에 적힌 도구는 **모든 프로젝트에서 자동으로** 쓸 수 있습니다.

## 지금 켜져 있는 것

| 도구 | 하는 일 | 왜 필요한가 |
|---|---|---|
| **Context7** (`.mcp.json`) | 라이브러리의 **최신 공식 설명서**를 찾아 읽음 | AI 가 옛날 방식으로 코드를 쓰는 실수를 줄임 (WPF, Expo 처럼 자주 바뀌는 것) |

> 처음 쓸 때 Claude Code 가 "이 MCP 서버를 허용할까요?" 라고 물으면 허용하세요.
> 클라우드 세션은 네트워크 정책 때문에 Context7 에 연결되지 않을 수 있습니다 — 내 PC 의 Claude Code 에서는 동작합니다.

## 따로 설치하지 않아도 이미 있는 것

| 기능 | 어디서 | 쓰임 |
|---|---|---|
| GitHub 검색·읽기·PR | claude.ai 에 GitHub 연결 시 | `/research` 에서 오픈소스 찾기 |
| 웹 검색 | Claude Code 기본 기능 | 오류 메시지·사용법 찾기 |
| 컴퓨터 화면 보기·조작 | Claude 데스크톱 앱의 *computer use* | 내 PC 에서 만든 프로그램을 Claude 가 직접 띄워 보고 확인 |

## 필요해지면 추가할 것 (선택)

| 도구 | 언제 | 추가 방법 (내 PC 터미널) |
|---|---|---|
| Playwright | `web` 유형 프로젝트를 브라우저로 자동 테스트할 때 | `claude mcp add playwright -- npx @playwright/mcp@latest` |

추가한 뒤 모든 프로젝트에서 같이 쓰고 싶으면 `--scope project` 를 붙이면 `.mcp.json` 에 저장됩니다.

## "리버스 엔지니어링 MCP" 를 넣지 않은 이유

GitHub 에는 Ghidra·IDA 같은 *실행 파일 분석기*를 Claude 에 연결하는 MCP 가 있습니다. 하지만 이 워크스페이스에는 맞지 않습니다.

1. **법적 위험** — 알PDF 같은 상용 프로그램의 실행 파일을 뜯는 것은 대부분 사용 약관 위반이고, 거기서 나온 코드를 쓰면 저작권 문제가 됩니다.
2. **효과가 낮음** — 실행 파일을 뜯으면 사람이 읽기 어려운 결과가 나옵니다. 초보가 기능을 더하기에는 오히려 멀리 돌아가는 길입니다.
3. **더 좋은 길이 있음** — 원하는 기능은 대부분 **이미 소스가 공개된 오픈소스**(예: 캡처는 ShareX)에 있습니다.
   `/research` 가 그 코드를 내려받아 "이 기능은 이 파일에서 이렇게 만들었다" 를 분석해 줍니다. 이것이 사실상 원하던 "분해해서 내 기능 넣기" 입니다.

상용 프로그램은 **화면과 기능 목록**을 참고합니다 — 스크린샷을 보여주면 Claude 가 그 화면 배치를 참고해 새로 만듭니다.
